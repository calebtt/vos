# S-07 — Actuator-held mic from a summon (#17)

**Needed by:** M0 decision (M0-05, #130). **Devices (2026-10-18):** **Phone B (Pixel 7 `panther`) on official GrapheneOS is the M0 gate device**, because plan §7 makes Phone B the default for all spikes and keeps Phone A (the daily phone with the only SIM) away from first runs. Confirm on Phone A (Pixel 8a `akita`, Graphene) afterward. Also: Phone C when it exists; emulator API 34/35 (gesture and tile only). The "Phone B on stock Pixel OS" leg is gone, because Phone B already runs GrapheneOS (read 2026-10-18). Running it needs a stock Pixel OS flash; see Result. Plan: TARGET-PLAN §6.0, §3.1 ("the assistant role belongs to the actuator"), §8 (Wed 10-14).

## Claim
Actuator-held mic: a `microphone` foreground service starts from a summon (assist gesture, MFB, QS tile) on stock GrapheneOS, Pixel stock Android 14–16, and Samsung; concurrent capture while another app records.

## Procedure
1. Throwaway test APKs (non-destructive, debug-signed): actuator with a `VoiceInteractionService` (assistant role) and a `microphone`-type foreground service; set it as the default assistant.
2. Instrument: log the input event time (`SystemClock.uptimeMillis` in the VIS/tile/MFB handler) and the first non-zero `AudioRecord` buffer time.
3. 20 summons per source per device, unlocked and locked. Sources: assist gesture; QS tile; classic BT headset long-press (HFP voice recognition); USB-C headset button (unlocked only — Graphene's USB-C port control blocks new connections while locked, §3.3); LE Audio button once that headset arrives.
4. Concurrent-capture leg: a fixture app is recording when the summon arrives; record whether VOS gets audio, the fixture gets silence, or both (no threshold; feeds S-31).
5. Pull logs to the desktop; compute p50/p95 per row.

## Pass criteria
On Graphene: p95 ≤150 ms (input event → first non-zero mic buffer) for the assist gesture, the QS tile and the classic BT button, unlocked and locked. Report: one row per source × device × lock state with pass/fail, p50, p95 and fallback used.

## Fallback
Session-UI activity as the foreground anchor.

## Result: PARTIAL (2026-10-18, Phone B, unlocked only)
Device: Pixel 7 `panther`, official GrapheneOS `CP3A.261005.002.A1` (Android 17, SDK 37). The probe is `spikes/probes/probe-s07` (debug, throwaway). It held the ASSISTANT role and a QS tile only during the run. Afterward the role went back to the previous holder (`com.amazon.dee.app`), the tile was removed and the probe uninstalled.

**QS tile, unlocked:** 20 real `input tap`s on the expanded tile, plus 2 `cmd statusbar click-tile`. **22/22 started the `microphone` FGS from the tile's `onClick`** (no `ForegroundServiceStartNotAllowedException`).

| Source | Device | Lock | Pass | p50 ms | p95 ms | Fallback |
|---|---|---|---|---|---|---|
| QS tile (tap) | Phone B Graphene | unlocked | **FAIL** (p95 > 150) | 166 | 176 (max 182) | — not needed for the FGS start itself |

- Breakdown (20 taps): handler → `startForeground` done p50 22.5 / p95 28 ms; `startForeground` → first non-zero `AudioRecord` buffer p50 144.5 / p95 150 ms. **Almost all of the latency is the cold `AudioRecord` start (HAL input-path open)**, not FGS permission. Likely fixes to test next: keep the input stream pre-opened while summon is possible, or use AAudio / MMAP low-latency input.
- Latency is measured from the handler, not the touch: input dispatch is not included, so the true numbers are slightly worse.
- **Assist gesture: not measured.** `cmd voiceinteraction show` needs `ACCESS_VOICE_INTERACTION_SERVICE`, which the shell doesn't have on a user build. The real gesture needs a human (Caleb), with the probe set as the assistant.
- **Locked leg: not run.** It needs the screen locked and then a human unlock (PIN), and the screen-off key may make a lock sound at night.
- Classic BT / USB-C / LE Audio buttons: not run (needs a headset and a human press).
- Concurrent-capture leg: not run.
- Related finding from S-08: a `microphone` FGS started by the actuator while it is only *bound* by the foreground session was **refused** (`SecurityException ... app must be in the eligible state`). Capture still worked through the capability the foreground session lent it with `BIND_INCLUDE_CAPABILITIES`. This matters for the actuator-owned-mic design (M0-05).
