# S-07 — Actuator-held mic from a summon (#17)

**Needed by:** M0 decision (M0-05, #130). **Devices (from #17):** Graphene phone (the M0 gate); Phone B on stock Pixel OS before unlock; Phone C; emulator API 34/35 (gesture and tile only). Plan: TARGET-PLAN §6.0, §3.1 ("the assistant role belongs to the actuator"), §8 (Wed 10-14).

## Claim
Actuator-held mic: a `microphone` foreground service starts from a summon (assist gesture, MFB, QS tile) on stock GrapheneOS, Pixel stock Android 14–16, and Samsung; concurrent capture while another app records.

## Procedure
1. Throwaway test APKs (non-destructive, debug-signed): actuator with a `VoiceInteractionService` (assistant role) and a `microphone`-type foreground service; set it as the default assistant.
2. Instrument: log the input event time (`SystemClock.uptimeMillis` in the VIS/tile/MFB handler) and the first non-zero `AudioRecord` buffer time.
3. 20 summons per source per device, unlocked and locked. Sources: assist gesture; QS tile; classic BT headset long-press (HFP voice recognition); USB-C headset button (unlocked only — Graphene's USB-C port control blocks new connections while locked, §3.3); LE Audio button once that headset arrives.
4. Concurrent-capture leg: a fixture app is recording when the summon arrives; record whether VOS gets audio, the fixture gets silence, or both (no threshold; feeds S-31).
5. Pull logs to the desktop; compute p50/p95 per row.

## Pass criteria
On Graphene: p95 ≤150 ms (input event → first non-zero mic buffer) for the assist gesture, the QS tile and the classic BT button, unlocked and locked. Report: one row per source × device × lock state with pass/fail, p50, p95 and fallback used.

## Fallback
