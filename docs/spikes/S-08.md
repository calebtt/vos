# S-08 — PCM pipe actuator → session, and platform AEC (#18)

**Needed by:** M0 decision (M0-05, #130). **Device:** Phone B (Pixel 7 speaker) and the emulator; classic BT headset (HFP). Plan: TARGET-PLAN §6.0, §3.1 (mic/speaker pipes as `ParcelFileDescriptor`), §8 (Wed 10-14).

## Claim
PCM over a `ParcelFileDescriptor` pipe, actuator → session, adds ≤10 ms. `AcousticEchoCanceler` in `MODE_IN_COMMUNICATION` on the Pixel 7 speaker.

## Procedure
1. Throwaway actuator + session test APKs signed with the same debug key. Actuator opens `ParcelFileDescriptor.createReliablePipe()`, hands the read end to the session over Binder.
2. Stamp each 20 ms 16 kHz frame with a monotonic timestamp at the actuator `AudioRecord.read` and at the session read; 10,000 frames; 30 min soak counting underruns.
3. Echo: `MODE_IN_COMMUNICATION`, `AcousticEchoCanceler.create(sessionId)` enabled; VOS speaks through the speaker at 70% volume. 20 turns with the owner silent (count self-interruptions); 20 turns with owner barge-in (count detections). Repeat on a classic BT headset (HFP).
4. If platform AEC misses either bar: run WebRTC AEC3 with VOS's own playback as reference against the same bars; record CPU cost (`dumpsys cpuinfo` / simpleperf).

## Pass criteria
- Pipe: ≤10 ms added at p95 over 10,000 frames; 0 underruns in 30 min.
- Echo: 0 self-interruptions in 20 silent turns; ≥18 of 20 barge-ins detected; repeated on BT HFP.

## Fallback
Larger buffers; software AEC (WebRTC AEC3).

## Result: PARTIAL (2026-10-18, Phone B)
Device: Pixel 7 `panther`, official GrapheneOS `CP3A.261005.002.A1` (Android 17, SDK 37). The probes are `spikes/probes/probe-s08-{actuator,session}` (debug, same key): an actuator mic `AudioRecord` at 16 kHz with 20 ms frames, sent through `createReliablePipe()` to the session.

- **Pipe, 10,000 frames: PASS.** Added latency p50 **0.79 ms**, p95 **1.17 ms**, max 5.85 ms; **0 underruns, 0 seq gaps**. The bar is p95 ≤10 ms.
- Actuator mic: 10,000 frames, 2 all-zero (startup). The actuator's own `microphone` FGS start was **refused** while it was only bound by the foreground session (`SecurityException: ... must be in the eligible state/exemptions to access the foreground only permission`). The mic still delivered audio because the session was in the foreground and bound with `BIND_INCLUDE_CAPABILITIES`. This is an input to S-07 / M0-05: the actuator needs its own eligible FGS-start moment (summon handler, VIS) or the privileged path on Tier P.
- 30-min soak (90,000 frames): see below.
- **Echo / AEC leg: not run** (needs speaker playback at 70% volume; night-time sound rule). Read-only: `/vendor/etc/audio_effects.xml` declares offload `aec` and `ns` effects for pre-processing.
