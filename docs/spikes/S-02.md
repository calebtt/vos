# S-02 — Product partition filesystem and `super` headroom (#10)

**Needed by:** M0 (M0-04, #129). **Device:** measure on Phone B (`panther`) first, confirm on `akita` (sizes can differ). Plan: TARGET-PLAN §6.0, §4.4 step 2.

## Claim
The filesystem type of Graphene's product partition, and whether `super` has headroom for +100 MB.

## Procedure
1. From the verified full OTA (no phone needed for steps 1–3): `avbroot ota extract --input <ota>.zip --directory <work> --partition product`.
2. `file <work>/product.img` and `dump.erofs`/`blkid` to record the filesystem type (erofs or ext4) and its size.
3. Record the unpacked size and the VOS overlay size (actuator + session APKs + XML + RRO; target +100 MB).
4. On Phone B (fastboot or root shell on the hello image): `lpdump` (or `lpdump /dev/block/by-name/super`) — record `super` size, group max size, used and free space per slot.
5. Repeat steps 1–4 on the `akita` OTA.

## Pass criteria
`lpdump` free space ≥ the overlay size on each target.

## Fallback
Put the overlay in `system_ext`; slim the APKs.

## Result: PASS on the desk for panther and akita (2026-10-19); earlier read-only checks (2026-10-18)
Phone B = Pixel 7 `panther` (serial ending E4, SKU GVU6C), official GrapheneOS build `CP3A.261005.002.A1` / incremental `2026100601` (Android 17, SDK 37, patch 2026-10-05), bootloader `cloudripper-17.0-15902555`, `ro.boot.flash.locked=1`, `verifiedbootstate=yellow`, `vbmeta.device_state=locked`, active slot `_b`, sandboxed Play installed (`com.google.android.gms`, `com.android.vending`).

- **Filesystem type (panther):** `/product` and `/system_ext` (and `/vendor`) are **ext4**, mounted `ro` (`/proc/mounts`: `/dev/block/dm-27 /product ext4 ro,seclabel,noatime`).
- Dynamic partitions on (`ro.boot.dynamic_partitions=true`); `super` → `/dev/block/sda30`; `product` is in `ro.product.ab_ota_partitions`.
- **Super headroom: not measured.** Block sizes under `/sys/block` give "Permission denied" to the shell UID, and `lpdump` needs root or fastbootd. Next: run `lpdump` on the unpacked full OTA's `super` metadata on the desktop (no device needed), or in fastbootd after unlock.
- akita: not measured.

**Desk measurement, 2026-10-19 (no device needed).** Source: build `2026101601` for each codename, from the factory image's `super_1.img` (unsparsed; `avbroot lp info` reads the LP metadata, the same data `lpdump` prints) and the full OTA's payload manifest (`avbroot payload info`: `dynamic_partition_metadata` and each partition's `new_partition_info.size`).

On Virtual A/B only the current slot's partitions live in `super`; an update's snapshot uses free `super` space first and then `/data`. Free space is ≥ 4.1 GiB on both devices, about 40× the 100 MB overlay target, so **pass**. The S-01 desk build grew `product` by 66 MiB (1,250,050,048 → 1,318,981,632 B) for the hello overlay plus the 64 MB margin.

Filesystem detail for S-01: Graphene's `product.img` is ext4 with `shared_blocks` (deduplicated; it cannot be written until unshared), 909 free blocks and 42 free inodes. `image/build.sh` grows, unshares and edits it without root (S-01 result).
