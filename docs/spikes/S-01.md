# S-01 — avbroot `--rootless --replace product` on the GrapheneOS OTA (#11)

**Needed by:** M0 decision (M0-04, #129). **Device:** Phone B (Pixel 7 `panther`) default smoke; the same recipe must build for `akita` (Phone A path). Plan: TARGET-PLAN §6.0, §4.4, §8 (Mon 10-19).

## Claim
avbroot `--rootless --replace product` on the current **GrapheneOS** panther OTA, with a hello priv-app that requests `MODIFY_AUDIO_ROUTING`, `CAPTURE_AUDIO_OUTPUT`, `CAPTURE_VOICE_COMMUNICATION_OUTPUT`, `CONCURRENT_AUDIO_RECORD_BYPASS` and `MEDIA_CONTENT_CONTROL`, boots and relocks with the owner's `avb_custom_key`.

## Procedure (Caleb, on the workstation and Phone B; not run by CI or agents)
1. Prerequisites: Day 0 done (`docs/runbooks/DAY0.md`): Graphene OTA cert pinned in `image/pins/`; full OTA for panther in `/media/caleb/UStor21/vos/firmware/panther/grapheneos/<build>/`. AVB and OTA keys in `~/.vos-keys/` (§5.4). Phone B: `fastboot flashing get_unlock_ability` returns `1`.
2. Verify the OTA against the pinned cert; record build number and SHA-256 (`sha256sum <ota>.zip`).
3. `avbroot ota extract --input <ota>.zip --directory <work>/extract --partition product`.
4. Unpack `product.img` with the tool for its filesystem type (S-02 result).
5. Add `/product/priv-app/VosHello/VosHello.apk` (hello priv-app requesting the five permissions above) and `/product/etc/permissions/privapp-permissions-vos.xml` granting them.
6. Repack with the original `file_contexts` and fs_config; add the AVB hashtree footer.
7. `avbroot ota patch --input <ota>.zip --key-avb ~/.vos-keys/avb.key --key-ota ~/.vos-keys/ota.key --cert-ota ~/.vos-keys/ota.crt --rootless --replace product <work>/product.img --output vos-panther-<build>-<sha>.zip`.
8. First flash (Phone B): unlock bootloader; flash the patched partitions (`avbroot ota extract --all`, then avbroot's initial-setup steps); `fastboot flash avb_custom_key avb_pkmd.bin`; boot.
9. `adb shell dumpsys package com.vos.hello | grep -A20 'install permissions'` — every permission above `granted=true`.
10. `fastboot flashing lock`; reboot; confirm the yellow boot state with the owner key.
11. Update path (M4-IMG-03): rebuild the overlay, patch a second same-key OTA, sideload it; boots locked with data intact.
12. Keep `image/build.sh` parameterized by codename so the same recipe builds for `akita`.

## Pass criteria
Boots locked (yellow state, owner key); all five permissions granted (`dumpsys package`); a second same-key OTA with a rebuilt overlay sideloads and boots locked with data intact.

## Fallback
Tier F with zero patches (§4.6 a); open the Tier F epic the same day; M1 continues on Tier S.
