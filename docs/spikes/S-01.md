# S-01 — avbroot `--rootless --replace product` on the GrapheneOS OTA (#11)

**Needed by:** M0 decision (M0-04, #129). **Device:** Phone B (Pixel 7 `panther`) default smoke; the same recipe must build for `akita` (Phone A path). Plan: TARGET-PLAN §6.0, §4.4, §8 (Mon 10-19).

## Claim
avbroot `--rootless --replace product` on the current **GrapheneOS** panther OTA, with a hello priv-app that requests `MODIFY_AUDIO_ROUTING`, `CAPTURE_AUDIO_OUTPUT`, `CAPTURE_VOICE_COMMUNICATION_OUTPUT`, `CONCURRENT_AUDIO_RECORD_BYPASS` and `MEDIA_CONTENT_CONTROL`, boots and relocks with the owner's `avb_custom_key`.

## Procedure (Caleb, on the workstation and Phone B; not run by CI or agents)

Steps 1–3 run on the desktop and need no phone. Steps 4–8 need Caleb's hands: the unlock and the lock each need a button press on the phone, and **each one wipes Phone B**.

1. **Owner keys, once:** `image/keys.sh` (prompts for two new passphrases; writes `~/.vos-keys/{avb.key,avb_pkmd.bin,ota.key,ota.crt}`). Store the passphrases in the password manager and copy `~/.vos-keys` to the offline USB stick before step 4.
2. **Hello APK:** `./gradlew -p spikes/probes :probe-s01-hello:assembleDebug` (package `com.vos.hello`, no code; requests `MODIFY_AUDIO_ROUTING`, `CAPTURE_AUDIO_OUTPUT`, `CAPTURE_VOICE_COMMUNICATION_OUTPUT`, `BYPASS_CONCURRENT_RECORD_AUDIO_RESTRICTION`, `MEDIA_CONTENT_CONTROL`).
3. **Image:** build from the Graphene OTA that matches the phone's build (`adb shell getprop ro.build.version.incremental`):

   ```bash
   image/build.sh --device panther \
     --ota /media/caleb/UStor2/vos/firmware/panther/grapheneos/2026101601/panther-ota_update-2026101601.zip \
     --overlay image/overlays/s01-hello \
     --add priv-app/VosHello/VosHello.apk=spikes/probes/probe-s01-hello/build/outputs/apk/debug/probe-s01-hello-debug.apk
   ```

   It verifies the input against `image/pins/`, adds the overlay to `product` (`/product/priv-app/VosHello/VosHello.apk`, `/product/etc/permissions/privapp-permissions-vos-hello.xml`), re-signs with `~/.vos-keys`, verifies the output against the owner keys, and writes `out/images/<YYYY-MM>/vos-panther-<build>-s01-hello-<git>.zip` plus a `.manifest.txt` on UStor2. Details: `image/README.md`.
4. **Before the wipe:** move everything Phone B holds that a wipe would lose (see Result, "Phone B is not empty"), then `adb pull` what is left to `/media/caleb/UStor2/vos/backup/phones/panther/<date>/`.
5. **Unlock and flash** (Phone B in the bootloader: `adb reboot bootloader`):

   ```bash
   fastboot flashing unlock                       # confirm on the phone; WIPES Phone B
   avbroot ota extract --input <vos-ota>.zip --directory /tmp/vos-flash --fastboot
   ANDROID_PRODUCT_OUT=/tmp/vos-flash fastboot flashall --skip-reboot
   fastboot erase avb_custom_key
   fastboot flash avb_custom_key ~/.vos-keys/avb_pkmd.bin
   fastboot reboot
   ```

6. **Check grants** (minimal setup, USB debugging on): `adb shell dumpsys package com.vos.hello | grep -A8 'install permissions'` shows the five permissions `granted=true`; S-03 steps 3–4 run here too.
7. **Relock:** `adb reboot bootloader`, `fastboot flashing lock` (confirm on the phone; **WIPES Phone B again**), boot. Pass: yellow boot screen with the owner key's ID; `getprop ro.boot.verifiedbootstate` = `yellow`, `ro.boot.flash.locked` = `1`. Leave OEM unlocking **on**.
8. **Update path** (M4-IMG-03): rebuild with a changed overlay against the same build, sideload it (`adb reboot sideload`, `adb sideload <zip>`), and check it boots locked with data intact.

The same recipe builds for `akita` (post-1.0 port, decision 40): `--device akita` with the akita OTA.

## Pass criteria
Boots locked (yellow state, owner key); all five permissions granted (`dumpsys package`); a second same-key OTA with a rebuilt overlay sideloads and boots locked with data intact.

## Fallback
Tier F with zero patches (§4.6 a); open the Tier F epic the same day; M1 continues on Tier S.

## Result: desk build PASS, flash PENDING (2026-10-19)
`image/build.sh` v0 built a VOS Image from `panther-ota_update-2026101601.zip` (the build Phone B runs) with throwaway test keys in the agent's scratch space (never `~/.vos-keys`), in 42 s on caleb-Z790, with no root:
- Input verified against `image/pins/grapheneos-ota-panther.crt`.
- Graphene's `product` is ext4 with `shared_blocks` (deduplicated, read-only) and 909 free blocks (3.6 MB), 42 free inodes. The script grows the raw image by the overlay size + 64 MB (`resize2fs`), unshares (`e2fsck -E unshare_blocks`; only 297 blocks were shared), adds the overlay with `debugfs` (root:root, 0755/0644, `u:object_r:system_file:s0`, the AOSP 2009-01-01 timestamp, as on Graphene's own files), reads every file back, requires a clean `e2fsck -fn`, and rebuilds the hash tree and FEC with `avbroot avb pack --recompute-size`.
- `avbroot ota patch --rootless --replace product` re-signed vbmeta and the OTA; the output passed `avbroot ota verify` against the test OTA cert and AVB key, and its `product` is byte-identical to the built one. `product` grew from 1,250,050,048 to 1,318,981,632 bytes (super headroom: S-02).
- Inode limit: the grow is smaller than one block group, so the inode count stays at 1280 and the overlay can add at most ~39 files and dirs. Enough for the hello image and the first real overlay; a bigger overlay needs `resize2fs` to a size that adds a block group, or `mke2fs` rebuild (open item for `image/build.sh` v1).

**Correction to the plan's permission list:** `CONCURRENT_AUDIO_RECORD_BYPASS` (§6.0 S-01 claim in this file, S-31) does not exist on Android 17. Phone B lists `android.permission.BYPASS_CONCURRENT_RECORD_AUDIO_RESTRICTION` (`signature|privileged`); the hello APK and allowlist use that name. Read on Phone B 2026-10-19: `MODIFY_AUDIO_ROUTING`, `CAPTURE_AUDIO_OUTPUT`, `CAPTURE_MEDIA_OUTPUT`, `CAPTURE_VOICE_COMMUNICATION_OUTPUT` and `CAPTURE_AUDIO_HOTWORD` are `signature|privileged|role`; `MEDIA_CONTENT_CONTROL` is `signature|privileged`; `DEVICE_POWER` is `signature|role|module` (not grantable to a product priv-app; matters for S-36).
