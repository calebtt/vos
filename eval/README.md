# eval — acceptance tests that run on a device

Test IDs come from TARGET-PLAN §6. Each runner pulls its results to the desktop: to `$VOS_EVAL_OUT` if set, else `$VOS_EVAL_ROOT/<date>/<test>-<time>/`, else under `eval/runs/` in the checkout (gitignored). On the workstation, `VOS_EVAL_ROOT` points at the eval runs directory on the data disk (§7). Nothing from a run is committed.

[`m1/lib.sh`](m1/lib.sh) holds the setup the M1 runners share (#268), sourced after a runner sets `ROOT`: `vos_run_dir`, `vos_daytime_only`, `vos_install_apps`, `vos_grant_mic`, `vos_grant_notifications`, `vos_seal_key_if_missing` (the key goes through `run-as` stdin, never an argument), `vos_clear_debug_overrides`, `vos_volume` and `vos_restore_media_volume` (through the debug summon activity: the shell's volume command does not apply on Android 17). A fix to one of them lands in every runner.

`m1/auth-probe/` is the on-device probe (`AuthProbe`, a plain `Instrumentation` with no AndroidX), compiled into the androidTest APKs and the fixtures. It reaches a service three ways: through `PeerLink` with the protocol-version handshake, by a raw `transact()` (the guard in `onTransact`), and by `Stub.asInterface()` (in the same process, a direct call on the Stub, so the guard inside each method). The two `ok` cases also time 200 guarded calls and record p50/p95 in `results.tsv`. With `-e probe mic` it runs `MicProbe` instead (M1-AUD-02: the session tries to record). `fixtures/auth/` builds two fixture APKs: `wrongpkg` (same debug cert, wrong package) and `foreign` (a throwaway key made in `build/` at build time).
