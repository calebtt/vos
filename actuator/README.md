# actuator — `com.vos.actuator`

Trusted base: sensors and hands, **no `INTERNET`** (TARGET-PLAN §3.1, §5.2).

- `ActuatorService` — the session's Binder entry (`IVosActuator`, from `:ipc`), guarded by the `com.vos.permission.SESSION` signature permission and by `BinderGuard` before any argument is read: exact caller package, the actuator's own signing cert, the grant table; refusals are audited to `files/audit/audit.jsonl` (§5.3, M1-AUTH-01). The session reports `turnReady` and `endTurn` here.
- `AudioPlane` — the one owner of what is heard and who holds the mic (§3.3). M1 skeleton: IDLE → CAPTURE (summon: pause playing media through its MediaController, transient focus, `MODE_IN_COMMUNICATION`, communication device = a headset if connected, else the speaker) → CONVERSE (the session's backend is ready) → RESTORE (mode, communication device, focus; resume media only if this turn paused it and the owner didn't pause it during the turn; re-pause a player that resumes itself) → IDLE. One audit line per transition (`{state, focus, mode, inDev, outDev, pausedPkg, mixes, turnId, reason}`); refused operations are audited too. A summon during a call is refused (HOLD's offline-only summon comes with the offline grammar). NOTICE, ANNOUNCE and APP_ASSIST are declared for M2/M4. `AndroidAudioPlatform` is its AudioManager/MediaSession side; media control needs the notification listener enabled.
- `TurnService` — the open turn, as a `microphone` foreground service. `VoiceTurn` captures 16 kHz mono (`VOICE_COMMUNICATION`, platform AEC and NS when available) into the mic pipe from the summon on, plays the session's reply from the speaker pipe as `USAGE_ASSISTANT` on the communication device, and on stop releases the mic first (logged as `AudioRecord.release … ms=`), then silences playback. A turn ends on the owner's stop (tile, notification), the session's `endTurn`, the session dying, an I/O error, or a 10-minute cap.
- `FastTools` — the fast tools the actuator runs for an owner turn (§3.2), each checked by its own oracle (P3): `time_get` (the clock), `volume_set` (a percentage, VERIFIED by reading the index back; a level the phone adjusts is UNVERIFIED with the real level; Do Not Disturb's refusal is FAILED), `volume_step` (up or down), `media_control` (media keys; VERIFIED from the playing session's state when the notification listener is enabled, else UNVERIFIED). Arguments from the session are validated here: an unknown tool or argument, or a value out of range, is FAILED without acting. `ActuatorService.callTool` runs them only for the turn the actuator opened while it is conversing (§5.6), writes one `tool.call` audit line per call, and plays the earcon for the actuator's verdict (`Earcons`: VERIFIED two rising tones, UNVERIFIED one low tone, FAILED two falling; logged instead of played when the debug speaker is a file). The owner's play or pause tells the AudioPlane what RESTORE must leave.
- `SummonTile` — the Quick Settings tile: summon, or stop the open turn. Exported only to the system (`BIND_QUICK_SETTINGS_TILE`, enforced by the policy check).
- `VosAssistService` (VoiceInteractionService), `VosAssistSessionService` and the stub `VosRecognitionService` — the assistant role (decision 45, §3.1). The assist gesture (long-press Home on 3-button navigation, the corner swipe on gesture navigation) shows `VosAssistSession`, which summons or stops a turn like the tile (the keyguard's voice-assist affordance shows the same session, through `showSession`); it has no UI and hides once the microphone service is in the foreground. Assist context (screen structure and screenshot) is disabled. All three are exported only to the system (`BIND_VOICE_INTERACTION`). `RoleWatch` audits each change of holder (`role.assistant`) and, while VOS is not the holder (another app, or none), shows a persistent notice that opens Default apps; it checks at start, after boot (`BootCheck`) and when the assistant service starts or stops. On a stock phone the notice needs notification permission (a setup step). Every summon logs S-07's line: from VOS getting the summon (the tile's click, the session's `onShow`) to the first non-zero mic buffer, with the start command, foreground, AudioPlane and recording steps.
- `DebugSummonActivity` (debug builds only, `src/debug`) — a summon the shell can start (guarded by `DUMP`); it can swap the mic for `files/debug/mic-inject.pcm` and the speaker for `files/debug/speaker-<turnId>.pcm`, so turns are tested without speaking or sound. For the echo test (#249) it can also open the live mic as in production and send `mic-inject.pcm` in place of its first frames (`mic_file_then_live`), and record from `MIC` with no AEC or NS (`raw_mic`, the control). Debug builds also log the live mic's level once a second (`mic level ... dbfs= played_bytes=`), with the reply bytes played meanwhile: levels only, never audio. Listed in `ci/exported-components-actuator-debug.txt`, which the release APK never gets.
- `HandsService` (AccessibilityService) and `NotificationsService` (NLS) — exported but guarded by the system-only `BIND_ACCESSIBILITY_SERVICE` / `BIND_NOTIFICATION_LISTENER_SERVICE` permissions, so only the system can bind them (M1). `HandsService` draws the indicator chip when it is enabled; its other hands (gestures, set-text) come later.
- `Indicator` and `IndicatorView` — the generating / acting indicator (Shell Contract row 13, #266). The actuator alone decides it:
  - GENERATING while a model call of the open turn is producing output. The session reports each call's start and end (`IVosActuator.modelCallStarted` / `modelCallEnded`, protocol 4), and those events carry no model output.
  - ACTING while the actuator runs a tool, which wins over GENERATING.
  - It clears when the turn ends or the owner stops, and it has no timeout, so a stalled call keeps spinning.
  - It is drawn as a `TYPE_ACCESSIBILITY_OVERLAY` chip by `HandsService` (top right, spinning ring while generating, amber ring while acting; placeholder art). The turn notification's title also says "VOS is thinking" / "VOS is acting", which is all a phone without VOS's accessibility service shows. `ci/policy_check.py` fails any exported service with one of these actions that lacks its guard.
- The manifest strips `INTERNET` with `tools:node="remove"`; `ci/policy_check.py` checks the built APK anyway.
- Depends on `:vtb-sdk` (the actuator hosts the VTB registry, §3.4) and `:ipc` (the session ↔ actuator contract).

Tests: `./gradlew :actuator:testDebugUnitTest` (`AudioPlaneTest`, `FastToolsTest`) and `:ipc:testDebugUnitTest` (`BinderGuardTest`, `PeerLinkTest`); on a device, `eval/m1/auth-01.sh` (M1-AUTH-01) `eval/m1/turn-pipes.sh` (turn pipes, #240) and `eval/m1/fast-tools.sh` (#245).
